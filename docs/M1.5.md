## 3. 与生产算法（§10.2）的关系：是抽离 + 两处必要修正

保留：四条信号（实体锚定、位置衰减 `1/(1+pos/20)`、命中密度、词面 2-gram）、
类型加分、`matched==0` 不入选、锚定池优先、格式化 `- [类型·重要度·日期] 正文`。

**修正 1：query / instruction 分离**（§10.3 case 6）
`recall(..., instruction=...)` 接受指令文本但**明确不参与匹配**（`del instruction`）；
生产只有私聊链路传了 `fallback_query`，群插话调用没传（`group_observation.py:6052-6067`），
这是本次复核发现的**未固化缺陷**；本包 API 从源头强制分离。

**修正 2：无锚时的覆盖度下限 + 契约/偏好不靠词面凑数**（§10.3 case 5）
- 无锚（无 context）时，查询的 idf 加权覆盖度必须 ≥ **0.25**，否则返回空；
- `contract`/`user_preference` **只有锚命中时才允许入选**（它们有专门注入面）。
  生产实测 "今天天气不错" 返回 850 字且 top1 是契约——本包返回空串（case5 修复）。

## 5. 已知局限（写进 README / 对外文档）

1. 启发式；一次问两件事只锚最近实体。
2. 锚定依赖 jieba；缺失时退化为纯词面（降级不报错）。
3. 无语义："这个项目"↔"石头门"只在上下文提过时成立。
4. 正解是 embedding：保留 `vector` 档接口（同一 `recall()` API，同一套 §10.3 用例）。
5. 语料必须按时间点回放，否则 case1–3 这种"后来记忆改变排序"不可复现。
