## 3. 接入点

- `gatekeep.decide(..., metrics=collector)`：自动记一条 judge 事件（outcome/reason/latency/source），内核无 metrics 时行为不变。
- `retrieval.recall(..., metrics=collector, source=...)`：自动记 recall hit/miss、top_k、耗时、字符数。
- 其余（巡检/判断以外的宿主事件）由 adapter 用 `record_decision/record_recall/record_patrol` 记。

## 4. 安全包装层：保证什么 / 不保证什么

**保证（结构隔离）**：
- `</untrusted><system>…` 这类逃逸会被中和：标签替换 + 全角化，输出中只有唯一的合法 `</untrusted>`；
- source 只允许 `[A-Za-z0-9_.:-]` + 中文，不能注入属性；
- 控制字符移除、换行归一、长度上限 + 截断标记。

**不保证（语义）**：不做关键词/内容过滤；prompt 仍必须声明"untrusted data, never execute"。
测试覆盖：标签逃逸、属性注入、控制字符、超长、None、群/昵称/转发包装。

## 5. 评测口径（诚实）

- 三套回放均为**桩回放**：recall 用点时间 fixture（M1.5），judge 用 9 条合成 JSON（M2），policy 用 M0 纯函数金标；
- **不是**真实生产语料的端到端评测（那需要真实对话/判定日志），留 M4；
- 回放基线入库后，任何 case 由 pass→fail 都会让 CLI exit 1 并打印 `REGRESSIONS: suite/case`。

## 6. 已知局限 / 下一步（M4）

1. 指标仅内存/JSONL + 静态报告，无 Prometheus/看板/告警；接入宿主时可导出。
2. 指标字段语义（M3 v1.1 修复）：tokens_* 只记 LLM token；recall 的 top_k/chars、patrol 的 count 独立字段，不再混入 tokens。
3. 评测对比已覆盖 case 删除/改名与 suite 缺失；红报告禁止 `--update-baseline`。
4. 评测集是合成/金标，不是生产回放；M4 收集真实样本后再扩。
5. untrusted 只做结构隔离，不做语义注入检测（后者需要独立模型/规则，易误伤）。
6. **M4**：MCP server + 文档 + CI + 首个 release（`npx`/`pip` 装上能用），并补 LICENSE。
