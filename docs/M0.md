## 3. 行为差异 / 设计取舍（不隐藏）

1. **巩固（episodic→auto_patrol）没有生产代码**：SOP 的"最凝练、信息最完整"是语义判断。
   M0 只做确定性的「最近 5 条窗口 → 按主题分组（≥2 次）→ 选 rank 最高 → 升格加 1（上限 9）」，
   语义 `theme_key` / `rank_key` 必须由调用方注入；M0 不编造关键词启发式。
   → 语义质量评测留到 M3。
2. **衰减（decay）没有生产代码**：按 SOP 字面实现。三处防御性取舍（SOP 未写、也不冲突）：
   `created_at` 不可解析/为 0 的行跳过（不把坏数据当"很老"）；`importance` 非整数或 `<= 0` 的行跳过；
   `archived` 行跳过（幂等，避免负数）。`contract` 永不衰减、`importance ≥ 7` 不衰减已实现。
3. **`build_sender_name_map`**：生产 SQL `GROUP BY sender_id` 取"任意一行名"；纯函数改为
   **按输入顺序取首个非空名**——语义等价，且结果确定。
4. **审计快照**：比对逻辑逐字保留（内容 md5 优先；变了再看台账是否点名；未点名则不刷新指纹、
   持续告警）。差异只在 IO：快照落盘改为 tmp + `os.replace` 原子写（生产为非原子写）。
   首次运行仍按生产语义把未点名文件全部报 suspicious。
5. **`finish` 闸门**：错误文案逐字保留，方便 M1 CLI 直接打印；`ledger_text=None` 表示台账文件缺失。
   `--user-end/--bot-end` 缺失的收尾拒绝（REFUSED）属于 CLI 层，留 M1。
6. **`intents` 0-1 importance 口径**：`imp<=1 → *10` 的 ORM 兼容分支原样保留（生产数据混口径）。
